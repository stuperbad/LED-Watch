# Firmware: toolchain and build

## C compiler (installed 2026-10-12)
`winget install ZakKemble.avr-gcc` (Zak Kemble's Windows build: AVR-GCC 16.1.0, Binutils 2.46.1, AVR-LibC 2.3.2, AVRDUDE 8.2, GNU Make 4.2.1; source https://github.com/ZakKemble/avr-gcc-build). It knows the AVR128DB48 natively (`-mmcu=avr128db48`, header `avr/ioavr128db48.h`).

Install folder (winget did not put the exe on the shell PATH of existing terminals):
`%LOCALAPPDATA%\Microsoft\WinGet\Packages\ZakKemble.avr-gcc_Microsoft.Winget.Source_8wekyb3d8bbwe\avr-gcc-16.1.0-x64-windows\bin`
A NEW terminal may find `avr-gcc` directly; otherwise use the full path or `firmware/c/build.ps1`.

## Build
```
cd firmware\c
powershell -File build.ps1 blink_test.c      # makes blink_test.elf and .hex and prints flash/RAM use
```
`avr-size` columns: flash used = text + data, RAM used = data + bss (AVR128DB48: 128 KB flash, 16 KB RAM).

## The C core (`c/watch.c`, `c/watch.h`)
A line-by-line port of `sim/watch_core.js` with no floating point and no hardware access (16-bit binary angles, Q8/Q16 fixed point). The same file is built for the AVR128DB48 and for the PC. It needs `ledmap.h` (generated by `gen_pins.py`).
API: `watch_init(seed)`, `watch_step(dt_real_ms, dt_sim_ms, &io)` with accelerometer in milli-g, buttons, VDD in mV, state of charge in per mille; read back `watch_fb()` (12 x 12 brightness) and `watch_scan()` (which rows and columns to drive, how long, within the 10 mA row-sink limit).
Differences from the JavaScript simulator: at most 40 particles instead of 60 (cheaper pair loop); orbit "ripple" levels agree to a few percent; the logging strings and the controls panel text exist only in JavaScript.

## Tests (run from `firmware/c/test`)
```
python gen_scenarios.py      # writes scn/*.scn (17 scripted button / motion / battery timelines)
python run_diff.py           # runs each on the JS simulator AND the C core, compares every frame (exact except a few animations)
python run_unit.py           # particle physics, bead, Ring Runner, the 999 award, scan limits, and a 400,000-step random-input stress run
```
Needs node and the host gcc (`winget install BrechtSanders.WinLibs.POSIX.UCRT`, installed 2026-10-12; path used by the scripts). Last result: all 17 scenarios match; unit and stress tests pass. The sanitizers (undefined-behaviour checking) are not available in this MinGW build, so integer-overflow bugs that only exist on the 16-bit AVR are guarded by coding rules (see the comment at the top of `watch.c`) and by compiling the real target with `-Wall -Wextra`.

## Size (real, linked for the chip)
`c/size_probe.c` links the core with a trivial main: 24,389 bytes of flash (19 %), 968 bytes of RAM (6 %) at `-Os`. Command:
```
avr-gcc -mmcu=avr128db48 -std=gnu99 -Os -I.. -ffunction-sections -fdata-sections -Wl,--gc-sections size_probe.c watch.c -o probe.elf && avr-size probe.elf
```

## The hardware layer (`c/hw/`)
Connects the portable core to the AVR128DB48. Everything compiles with avr-gcc (`powershell -File c\build_fw.ps1` -> `c/hw/watch_fw.hex`); **none of it has run on a board yet** (`c/BRINGUP.md` is the guide for that day).
| File | What it does |
|---|---|
| `main.c` | the loop: sleep, read inputs, `watch_step()`, draw; power-on self-test on the indicator LEDs |
| `matrix.c`, `matrix_map.c` | LED matrix scan: timer interrupt that lights one row-slot at a time, brightness by per-column switch-off times; pin masks are built from the generated `hwmap.h` |
| `clock.c` | 4 MHz main clock, 32.768 kHz crystal, RTC counter = all timekeeping, periodic wake-up (64 Hz awake, 1 Hz asleep) |
| `buttons.c` | the two buttons, accelerometer interrupt pin and BAT_OK (port E), wake from sleep on pin change |
| `vbat.c` | battery voltage from the ADC's internal VDD/10 input |
| `i2c_twi.c`, `imu.c` | I2C host (TWI0) and the LIS2DW12 accelerometer driver (register map from datasheet DS11811) |
| `hw_pure.c` | the calculations with no hardware in them: debounce, battery curve, time conversion, accelerometer scaling, wrist-raise classifier |
| `hw_config.h` | every number that must be tuned on the real board |
PC tests of the hardware-free parts: `python c/test/run_hw.py` (161 checks: pin map, scan timing, debounce, battery maths, accelerometer register sequence against a pretend sensor, raise detection).
`gen_pins.py` now also writes `hwmap.h` (every pin as a port letter and bit number) so the C code builds its masks from the schematic.

## Size (real, linked for the chip)
Whole firmware (`build_fw.ps1`): **29.4 KB of flash (22 % of 128 KB) and 2.2 KB of RAM (13 % of 16 KB).** The portable core alone (`size_probe.c`) is 24.4 KB / 1 KB.
